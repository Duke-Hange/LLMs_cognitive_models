# 划分策略详解 - 实验人员视角

## 为什么需要划分策略？

在机器学习实验中，我们不能用训练数据来测试模型，否则就像"开卷考试"——模型只是记住了答案，而不是真正学会了。因此，我们需要将数据分成**训练集**和**测试集**：

- **训练集**：模型学习的数据
- **测试集**：评估模型真实能力的数据

不同的划分策略测试的是模型**不同方面的能力**。对于 Choices13k 项目，我们设计了 5 种划分策略，每种都回答不同的科学问题。

---

## 策略 1: Problem-Split（问题划分）

### 🎯 测试目标
**模型能否预测从未见过的新问题？**

### 📖 通俗解释
这是最基础的划分方式，就像：
- **训练集**：给模型看 80% 的问题（比如问题 1-10,000）
- **测试集**：让模型预测剩下的 20% 的问题（比如问题 10,001-13,006）

### 🔬 科学问题
- 模型是"死记硬背"了训练问题，还是真的理解了决策规律？
- 模型能否将学到的规律应用到新问题上？

### 💻 实现方式
```python
# 随机选择 80% 的问题作为训练集，20% 作为测试集
train_problems = [1, 3, 5, 7, ...]  # 随机选择的 10,000 个问题
test_problems = [2, 4, 6, 8, ...]    # 剩下的 3,006 个问题
```

### 📊 预期结果
- **好模型**：在测试集上表现接近训练集（说明学到了通用规律）
- **差模型**：训练集表现好，测试集表现差（说明只是记住了训练数据）

### ⚠️ 局限性
这种划分相对"宽松"，因为测试问题和训练问题在结构上可能很相似（都是风险选择问题）。

## 策略 2: Feedback-Split（反馈条件划分）⭐ **最重要**

### 🎯 测试目标
**模型能否理解反馈的作用？能否从"有反馈"迁移到"无反馈"？**

### 📖 通俗解释
这是最关键的划分，测试模型是否真正理解了**反馈机制**：

- **训练集**：所有**有反馈**的问题（Feedback = True）
  - 被试选择后能看到实际获得的奖励
  - 模型学习"从经验中学习"的决策
  
- **测试集**：所有**无反馈**的问题（Feedback = False）
  - 被试选择后看不到结果
  - 模型需要预测"仅凭描述做决策"的行为

### 🔬 科学问题
这是认知科学中的核心问题：
- **决策从经验（Decisions from Experience）** vs **决策从描述（Decisions from Description）**
- 人类在有反馈时会学习，无反馈时只能凭描述判断
- **模型是否也理解这种差异？**

### 💡 实际例子
想象两个场景：

**场景 A（有反馈，训练集）**：
```
问题：选择 Gamble A 还是 B？
你选择了 A，获得了 26 点 ✓
你看到如果选 B，会获得 21 点
→ 你从这次经验中学习
```

**场景 B（无反馈，测试集）**：
```
问题：选择 Gamble A 还是 B？
你选择了 A
→ 你不知道结果，只能凭描述判断
```

### 💻 实现方式
```python
# 训练集：所有有反馈的问题
train = df[df['Feedback'] == True]   # 约 10,000+ 条

# 测试集：所有无反馈的问题  
test = df[df['Feedback'] == False]   # 约 800+ 条
```

### 📊 预期结果
- **好模型**：能够理解反馈的作用，在两种条件下都能预测
- **差模型**：只在有反馈时表现好，无反馈时表现差（说明没理解反馈机制）

### ⭐ 为什么最重要？
1. **科学意义**：这是区分"真正理解"和"死记硬背"的关键
2. **机制验证**：如果模型能通过这个测试，说明它理解了反馈在决策中的作用
3. **现实意义**：很多真实决策场景是没有反馈的（比如选择职业、投资等）

## 策略 3: Parameter-Split（参数空间划分）

### 🎯 测试目标
**模型能否将学到的规律推广到不同的参数空间？**

### 📖 通俗解释
测试模型是否捕捉到了**深层规律**，而不仅仅是表面的模式：

- **训练集**：某种类型的问题（如"期望值差异小"的问题）
- **测试集**：另一种类型的问题（如"期望值差异大"的问题）

### 🔬 科学问题
模型是否理解了：
- 期望值差异如何影响选择？
- 模糊性（Ambiguity）如何影响决策？
- 风险水平如何影响选择？

### 💡 实际例子

**方式 A：按期望值差异划分**
```python
# 训练集：两个选项期望值接近的问题（EV_diff < 5）
# 例如：Gamble A 期望值 10，Gamble B 期望值 12（差异小）

# 测试集：两个选项期望值差异大的问题（EV_diff >= 5）
# 例如：Gamble A 期望值 5，Gamble B 期望值 20（差异大）
```

**方式 B：按模糊性划分**
```python
# 训练集：概率信息明确的问题（Amb = False）
# 例如：Gamble B 的概率是 0.3（明确告诉你）

# 测试集：概率信息模糊的问题（Amb = True）
# 例如：Gamble B 的概率"不确定"（存在模糊性）
```

**方式 C：按风险水平划分**
```python
# 训练集：低风险问题（收益波动小）
# 测试集：高风险问题（收益波动大）
```

### 💻 实现方式
```python
# 方式 A：按 EV_diff 划分
train = df[df['EV_diff'].abs() < 5.0]   # 期望值差异小
test = df[df['EV_diff'].abs() >= 5.0]  # 期望值差异大

# 方式 B：按模糊性划分
train = df[df['Amb'] == False]  # 明确概率
test = df[df['Amb'] == True]    # 模糊概率

# 方式 C：按相关性划分
train = df[df['Corr'] == 0]     # 无相关
test = df[df['Corr'] != 0]      # 有相关（正或负）
```

### 📊 预期结果
- **好模型**：在不同参数空间都能预测（说明理解了深层规律）
- **差模型**：只在训练的参数空间表现好（说明只是拟合了表面模式）

### 🎓 类比
就像学数学：
- **差学生**：只会做"x + 5 = 10"这种题（训练集类型）
- **好学生**：也会做"2x - 3 = 7"这种题（测试集类型，虽然形式不同但原理相同）

## 策略 4: Block-Split（区块划分）

### 🎯 测试目标
**模型对问题呈现顺序是否敏感？**

### 📖 通俗解释
测试模型是否受到**顺序效应**的影响：

- **训练集**：Block 1-3 的问题（较早呈现的问题）
- **测试集**：Block 4-5 的问题（较晚呈现的问题）

### 🔬 科学问题
- 人类决策是否会受到问题呈现顺序的影响？
- 模型是否也表现出这种顺序效应？
- 模型是否"记住"了顺序，还是真正理解了问题本身？

### 💡 实际例子
在实验中，问题可能按以下顺序呈现：
```
Block 1: 问题 1-100（简单问题）
Block 2: 问题 101-200（中等难度）
Block 3: 问题 201-300（较难问题）
Block 4: 问题 301-400（混合难度）
Block 5: 问题 401-500（混合难度）
```

### 💻 实现方式
```python
# 训练集：Block 1-3
train = df[df['Block'].isin([1, 2, 3])]

# 测试集：Block 4-5
test = df[df['Block'].isin([4, 5])]
```

### 📊 预期结果
- **理想情况**：模型不受顺序影响，在 Block 4-5 也能预测
- **如果表现差**：可能说明模型"记住"了顺序，而不是理解了问题

### ⚠️ 注意事项
这个划分相对较弱，因为 Block 本身可能没有很强的科学意义，主要用于检查模型是否过度拟合了顺序信息。

## 策略 5: Cross-Validation Split（交叉验证）

### 🎯 测试目标
**模型性能的稳定性如何？**

### 📖 通俗解释
这是最严格的验证方式，将数据分成 K 份（通常是 5 份），每次用其中 4 份训练，1 份测试，重复 5 次：

```
第 1 次：用问题 1-10,000 训练，问题 10,001-13,006 测试
第 2 次：用问题 2,601-13,006 训练，问题 1-2,600 测试
第 3 次：用问题 1-2,600 + 5,201-13,006 训练，问题 2,601-5,200 测试
...（共 5 次）
```

### 🔬 科学问题
- 模型性能是否稳定？
- 结果是否依赖于特定的数据划分？

### 💻 实现方式
```python
from sklearn.model_selection import KFold

kf = KFold(n_splits=5, shuffle=True, random_state=42)
for train_idx, test_idx in kf.split(problem_ids):
    train = df[df['Problem'].isin(problem_ids[train_idx])]
    test = df[df['Problem'].isin(problem_ids[test_idx])]
    # 训练和评估模型
```

### 📊 预期结果
- **好模型**：5 次交叉验证的结果应该相似（说明性能稳定）
- **差模型**：结果波动大（说明可能过拟合或数据划分敏感）

### ⭐ 优势
- 最严格的验证方式
- 可以得到性能的置信区间
- 减少因数据划分带来的偶然性

## 划分策略的选择建议

### 🥇 主要实验（必须做）

1. **Feedback-Split** ⭐⭐⭐
   - **为什么最重要**：测试模型是否理解反馈机制
   - **科学价值**：区分"真正理解"和"死记硬背"
   - **建议**：这是核心实验，必须做

2. **Parameter-Split** ⭐⭐
   - **为什么重要**：测试模型是否理解深层规律
   - **科学价值**：验证模型的抽象能力
   - **建议**：至少做一种（推荐按 EV_diff 或 Amb 划分）

### 🥈 辅助实验（建议做）

3. **Problem-Split** ⭐
   - **为什么做**：基础泛化测试
   - **科学价值**：验证模型不是死记硬背
   - **建议**：作为基线实验

4. **Cross-Validation** ⭐
   - **为什么做**：验证结果稳定性
   - **科学价值**：提供置信区间
   - **建议**：如果时间允许，建议做

### 🥉 可选实验

5. **Block-Split**
   - **为什么做**：检查顺序效应
   - **科学价值**：相对较弱
   - **建议**：如果发现顺序效应，可以深入分析

## 实验设计建议

### 阶段 1：探索性分析
1. 先做 **Problem-Split**，了解模型的基础能力
2. 检查数据分布，了解不同划分的数据量

### 阶段 2：核心实验
1. **Feedback-Split**（最重要）
   - 这是区分模型能力的关键实验
   - 如果模型通过这个测试，说明它理解了反馈机制

2. **Parameter-Split**
   - 选择 1-2 个重要参数（如 EV_diff, Amb）
   - 测试模型的抽象能力

### 阶段 3：稳健性验证
1. **Cross-Validation**
   - 验证结果的稳定性
   - 提供性能的置信区间

2. **Block-Split**（可选）
   - 如果发现顺序效应，可以深入分析

## 常见问题

### Q1: 为什么不能只用 Problem-Split？
**A**: Problem-Split 太"宽松"了。测试问题和训练问题在结构上很相似，模型可能只是记住了模式，而不是理解了机制。Feedback-Split 和 Parameter-Split 能更严格地测试模型的理解能力。

### Q2: Feedback-Split 的数据不平衡怎么办？
**A**: 确实，有反馈的问题（~10,000）远多于无反馈的问题（~800）。可以：
- 使用加权损失函数
- 在评估时分别报告两种条件下的性能
- 使用分层采样确保代表性

### Q3: 多个划分策略的结果不一致怎么办？
**A**: 这是正常的！不同划分测试不同方面：
- Problem-Split 表现好 → 模型能泛化到新问题
- Feedback-Split 表现好 → 模型理解反馈机制
- Parameter-Split 表现好 → 模型理解了深层规律

如果某个划分表现差，说明模型在那个方面有局限性，这正是我们要发现的！

### Q4: 应该先做哪个划分？
**A**: 建议顺序：
1. **Problem-Split**（快速了解基础能力）
2. **Feedback-Split**（核心实验）
3. **Parameter-Split**（深入验证）
4. **Cross-Validation**（稳健性验证）

---

## 总结

不同的划分策略就像不同的"考试题目"：
- **Problem-Split**：基础题（能否做新题？）
- **Feedback-Split**：核心题（是否理解反馈？）⭐
- **Parameter-Split**：拔高题（能否举一反三？）
- **Block-Split**：附加题（是否受顺序影响？）
- **Cross-Validation**：综合测试（性能是否稳定？）

**记住**：Feedback-Split 是最重要的，因为它测试的是模型是否真正理解了决策机制！
